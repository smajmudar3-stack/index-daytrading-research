# Public GitHub sweep: options strategies claiming high returns, code-audited

**Date:** 2026-08-19
**Question:** Of the options strategies published on public GitHub that claim high returns, which claims survive a code-level audit?

**Answer: none of the high ones.** Across 1,233 distinct repositories found and ~90 audited at source level, **not one repo pairs a large positive return claim with a methodology that survives reading the code.** Every high-claim repo had at least one defect large enough to account for its entire result, and in most cases the defect is a single identifiable line.

The sweep did find something worth having, just not what was being looked for. **Two positive claims survive audit — both modest (Sharpe 0.38–0.72, CAGR 3.6–13.5%), both arguably still nulls.** And a cluster of repos with genuinely correct methodology all independently reproduce the local calibration: on real bid/ask with the spread crossed, systematic option selling and far-OTM buying are flat-to-negative. Two of them measured it on data this project does not have (ORATS 1-minute NBBO across 303 names; 952 days of SPXW 0DTE minute quotes) and got the same answer.

---

## Method

Two independent sweeps of public GitHub, then a source-level audit of every candidate carrying a return claim.

**Sweep 1 — repository search.** 44 queries × 2 sort orders (stars, recently-updated), 30 results each, via the authenticated GitHub repositories API. Themes: options backtesting engines; 0DTE / weeklies / LEAPS; wheel / covered call / cash-secured put; iron condor / butterfly / calendar / diagonal / ratio spread / jade lizard / strangle; volatility arbitrage, dispersion, VIX term structure, variance swaps; gamma scalping and delta hedging; earnings and IV crush; ML and RL option selection; unusual options flow; broker automation (IBKR, tastytrade, Schwab, Alpaca, Robinhood, Upstox, 5paisa, Angel One); and explicit profitability phrasing. → **643 distinct repositories.**

**Sweep 2 — code search.** 30 queries against README and doc file *contents* for advertised performance figures ("annualized return", "CAGR", "win rate", "profit factor", "Sharpe ratio", "turned $", "monthly return") crossed with each structure name. → **590 further repositories**, enriched with stars and last-push date.

**Audit.** Every repo with a return claim was shallow-cloned and read. Trusting a README was disallowed by construction: verdicts rest on the backtest source, the committed data, and where possible on re-running the code — several results below are marked *reproduced*, meaning the repo's own script or ledger was re-executed to isolate the defect. A standard red-flag grep (mid fills, `bid > 0` exit filters, cost modelling, whole-sample fits, missing time-to-expiry in exit valuation, synthetic Black-Scholes pricing) was the entry point, never the conclusion.

**Calibration used to judge plausibility** (measured locally on real SPY bid/ask, 2008–2025): every option credit structure — condor, butterfly, jade lizard, strangle, credit spread — is negative expectancy, all |t| > 9. Far-OTM buying is −45.6% overall, +5.6% filtered to ≤20% bid/ask spread. Buying straddles into earnings is −35.0% (t = −95.7). CBOE's own iron condor index CNDR has lost money for 15 years. Against that baseline, a large positive return from systematic premium selling is a bug report until proven otherwise.

The distribution is the finding in miniature. The field is overwhelmingly zero-star, recently-created, single-author repositories, and that is where essentially all of the high return claims live. The handful of well-starred projects are *engines* and *libraries* that make no performance claim at all — and they are the ones whose fill models are correct.

## What actually killed these results

Frequency across the ~80 repos audited, with the canonical example of each.

**1. The option price was never a market price (most common, and worst).**
More than half of the repos claiming a return never had an option quote at all. They manufacture a premium from a volatility number the author chose, which fixes the sign of the result before any data is read:
- `iv = vix * 1.6` — oyzh888/0dte-options-strategy `backtest.py:85`
- `iv = trailing_realized_vol * 1.18` — adityaalle1/OptionsBT `optionsbt.html:1790`
- `iv = (vix/100) * multiplier * (1 + wing_pct*12)` — aboutdomtime/condor-lab `Main.py:171-191`
- `--gbm-vol 0.18` path vs `--base-iv 0.20` chain — mitchellray-gh/0DTEOptions `spread_backtest.py:166-167`
- `iv = realized_vol + 0.02` — karolkudlacik `simulation.py:141-158`
- `rv = iv * 0.80` — tfrmma/options-vrp-harvester `utils/backtester.py:127-155`
- `implied_vol = VIX/100`, one flat vol for every strike, no skew — ccharafeddine/spx-income-trader `sim_broker.py:146`

In each case the "volatility risk premium the strategy harvests" is a constant in the source. Neutralise it and the strategy loses. This is a more dangerous failure than a mid-price fill, because there is no spread you could widen to fix it.

A close variant is **freezing IV after entry**: willhammondhimself/adaptive-volatility-arbitrage marks every position with `sigma = pos.implied_volatility`, and the update call omits the `implied_vol` argument, so a strategy whose entire thesis is "IV converges to RV" can never record a change in IV — deleting exactly the vol-spike losses that are the only way a short straddle loses.

**2. Mid-price fills.** Confirmed in optopsy's `slippage="mid"` mode, OptionSuite (`csvData.py:204-206`), lumibot's `SMART_LIMIT`, AlphaGEX (8 crossings per condor round trip), thunderscarf, CLDE, mrajpurohit1912, chicago-joe, TradeBlocks, joaquinbejar's default naive mode, OliverBarbeau (exit only). Where it could be quantified it was decisive every time: thunderscarf goes from **+$7.09/trade to −$2.91 on $0.10 of round-trip spread**; jakehanson's +2.115% goes to **−1.88% (t = −5.10)** at 2%/leg.

**2b. Fills at prices the market never printed.** A distinct sibling of the mid-price fill, and in two cases more brazen. emlama/gex-backtesting buys a **long** put at the bid and calls it "worst fill" in its own docstring — for a long, the bid is the *best* possible fill, and both "bid" and "mid" are actually quantiles of the trade-print distribution rather than quotes. acetaldehyde14/quickopttrades books exits at *exactly* the ±5% band whenever a 1-minute bar's high or low touches it, with no bid/ask in the pipeline; its own logs show **172 of 498 consecutive same-contract pairs stop out and re-enter higher the very next minute, median +4.75% above the stop-out fill** — the band is being triggered by intrabar quote bounce and filled as if it were a print.

**3. Exit-chain survivorship.** Actively hunted; found **once** as the classic `bid > 0` pattern, and hidden — cutemarkets/cutebacktests `intraday_pricing.py:530`, where `exit_quote_bid > 0` combined with `FALLBACK_TO_BAR_CLOSE=False` silently drops any long option that expired worthless. It never appears as a data filter, only as a rejection counter. Near-misses: OliverBarbeau `thetadata.py:492-493`, and CLDE's stop-loss check nested inside `if current_price is not None`, so a missing row means no stop is ever evaluated.

The *equity-side* equivalent turned up too, and is just as destructive: SC4RECOIN/FlowAlgo-Options-Trader builds its tradable universe from `alpaca.list_assets(status="active")` **at run time in 2021** and then filters 2017–2020 alerts against it (`backtest.py:15-17,182`), deleting every delisting and bankruptcy from a long-only backtest — and separately zeroes the P&L of any position that moved more than 50%, printing *"Ignoring position results"* (`:211-217`).

**4. Naked short legs outside the capital-at-risk denominator.** rajmaurya0904/bhav (`strategy.py:93` gates the buying-power check on `qty > 0`, so shorts skip it), ArnMehta11 (premium not margin; worst trade −$1,942 on a nominal $1,000), MortonSam (size = 5% of equity ÷ premium collected), chrislernunes (one index lot while short five stock straddles), CLDE, mdsohelmondal, mrajpurohit1912. The single counter-example worth copying is **sirnfs/OptionSuite**, which implements real Reg-T 20%/10% strangle buying power.

**5. Overlapping trades inflating t-stats.** ArnMehta11 is the clean demonstration: 457 "trades" are ~101 earnings events emitted once per offset-grid cell, and **t collapses 4.13 → 1.62** on event clustering, → 2.21 across only 7 tickers. naeemsem97's analysis notebook counts every trade **four times** by iterating QuantConnect's overlapping M1/M3/M6/M12 `rollingWindow`. Also condor-lab's `--daily` mode and jakehanson's 2,854 straddles across 160 correlated names in 4 seasons.

**6. Look-ahead.** Three distinct flavours:
- *Same-bar*: `spx_at_entry = spx_close` (iulianallroad `backtest.py:744`), thunderscarf's inclusive `to=` handing the 09:45 entry today's 16:00 close, bhav's `_price_at` filling at the current bar's close, and the most elaborate case — ccharafeddine/spx-income-trader **synthesises its 30-minute bars from the daily close** (`data_loader.py:79-95`), so a morning "pulse bar" signal is a function of the close of the day it trades.
- *Window overlap*: emlama/gex-backtesting computes its gamma metric over `[t, t+5min)` and enters at `t` — five minutes of future flow inside the signal.
- *Whole-sample*: MortonSam's universe filter keeping tickers whose **full-sample** average move beat the premium; oyzh888 relabelling HMM states with full-sample returns inside a walk-forward; kurveakshay re-fitting the scaler on the test set.
- *Random shuffle on time series*: nataliaburrey's `train_test_split` default.

**7. Losses that cannot happen.** Losses capped at exactly −10% of credit (iulianallroad `:440-442`) or −2× credit assuming a perfect touch fill (condor-lab); stops filled at the trigger price after a bar has already gapped through (mdsohelmondal — **140 of 246 fills better than the stop**, umeshpalai, bhav); and one outright sign error that books losses as gains (revred/ODTE `FixedFitOptimizer.cs:321`).

**8. Exit valuation with no time-to-expiry.** MortonSam `:251` (intrinsic-only buy-back on contracts with up to 60 DTE), pablofelipe01 `backtester.py:791-825`, iulianallroad `:322` (linear in distance-OTM), kunalrbhatia `:307` (missing quote → entry price → zero P&L).

**9. Numbers no code produces.** u3ffrzi (README-only repo, 10–15%/month), iampratyush4 (CAGR 12.7 / Sharpe 1.35 appear nowhere in the source, and the backtest has never executed), thunderscarf (3 of 5 headline figures — its own notebook prints EV $1.06e15), mitchellray-gh ("82%" appears only in a README and a comment), adityaalle1 ("bid/ask spread baked in" is UI copy over a file with no bid or ask variable), acetaldehyde14 (README's +60% / 90% win rate matches none of the four scripts' actual TP/SL parameters), joaquinbejar/OptionStratLib (README advertises a "comprehensive backtesting engine"; `BacktestResult` is never constructed anywhere in the repo), bluedabadi (the "25% annual return" is today's theta × 250 with no gamma, vega or loss term).

**10. Accuracy sold as return.** nataliaburrey (75% accuracy on 16 rows → +1913%), kurveakshay (70.77% is in-sample binary accuracy from a regression model), auto-d1dact (short puts evaluated purely by breach frequency), DerekNigten (90.7% hit rate on a highly persistent IV slope — though this author reports the Sharpe instead).

## If you want to backtest something against your own real-quote data

Only two candidates are worth the time, and both are specified precisely enough to reimplement.

### A. Short ATM straddle, SPY (anthonymakarewicz/volatility-trading)

- **Underlying:** SPY, daily chain, DTE ∈ [5, 60]
- **Structure:** sell 1 put at delta −0.50 and 1 call at delta +0.50, same expiry
- **DTE at entry:** target 30, tolerance ±7
- **Entry trigger:** unconditional — always short, daily EOD, no intraday timing
- **Exit:** mechanical roll every 10 trading days, same-day re-entry allowed. No profit target, no stop
- **Delta hedge:** disabled in the baseline
- **Sizing:** `risk_budget_pct = 1.0`, `margin_budget_pct = 0.40` of equity under Reg-T; realised 4–7 contracts
- **Costs:** buy at ask + $0.01, sell at bid − $0.01, $1.00/leg commission, cash earns DGS3MO, borrow at DGS3MO + 200bp
- **Reported:** $50,000 start, **2011-01-01 → 2017-12-31, 228 trades, Sharpe 0.38, CAGR 3.55%, max DD −16.09%, PF 1.36, win 63.60%**
- **The test that matters:** rerun it 2008–2010 and 2018–2025. The reported window is short vol's best-ever run and excludes both Feb-2018 and Mar-2020. If it survives those, it is interesting; if not, it is a regime artifact.

### B. 25-delta skew risk reversal, SPX (same repo)

- **Underlying:** SPX, ORATS chain
- **Structure:** 25-delta risk reversal, 30 DTE, signal from a **backward-looking rolling z-score** of the skew
- **Costs:** same bid/ask + slippage + commission model as above; hedge is static, set once at entry
- **Reported:** **2016–2023, 78 trades, Sharpe 0.61, CAGR 10.73%, max DD −14.61%**
- **The problem:** 78 trades at Sharpe 0.61 → **t ≈ 1.7**. Not significant. The repo reports no t-stat or DSR. Before backtesting it, decide what trade count would settle the question — on ~33 trades/yr you need roughly a decade more data to reach t = 3.

### C. The negative control worth reproducing

`malithakabir/orats-option-backtest` — weekly debit verticals across 303 symbols on 1-minute ORATS NBBO, entered at the ask and sold at the bid, spread filter at 15% of bid, settled at intrinsic. **Pooled −2.98%/trade, t = −2.90, n = 23,713.** This is an independent measurement of the same thing measured locally, on data this project doesn't have, and it agrees. It is also a clean demonstration of why bucket means need a standard deviation printed next to them: its own advertised +11.69% bucket is t = 0.72.

## Bottom line

**There is no high-return options strategy on public GitHub that survives a code audit.** The distribution is stark: claims scale inversely with methodological quality. The repos claiming +20,376%, +10,941%, +1,703%, +690%, +341%, +227%, Sharpe 25.4, Sharpe 13.5 and Sharpe 6.83 are broken in ways that are individually diagnosable and usually reducible to one line. The repos that get the fills, the denominator and the statistics right report **Sharpe 0.38, Sharpe 0.61, +0.49% net, −2.98%/trade, or a null** — and several explicitly falsify their own thesis in writing.

That distribution is itself the answer. Six independent, well-built projects using data this project does not have — ORATS 1-minute NBBO across 303 names, 952 days of SPXW 0DTE minute quotes, QuantConnect OPRA, ThetaData chains, measured earnings fills — all land in the same place as the local calibration. On real bid/ask with the spread crossed, systematic premium selling and far-OTM buying are flat to negative. Nobody on GitHub has found the exception; the ones claiming to have found it have found a bug.

The transferable assets from this sweep are not strategies:
- **`goldspanlabs/optopsy`** (`slippage="spread"` default) and **`lambdaclass/options_portfolio_backtester`** (`MarketAtBidAsk` default, intrinsic fallback, split-adjustment invariant) as engines to build on.
- **`sirnfs/OptionSuite`** `strangle.py:156-186` as the reference Reg-T buying-power calculation for naked short legs.
- **`csnyder256`**'s three-ledger design where **the worst ledger grades**, and its capital-at-risk basis that caps wins but never floors losses.
- **`chiehchiYang/optionpilot`** `strategies.py:118-127` — detecting overlapping-sample inflation and *withholding the number* rather than printing it with a caveat.
- **`randomwalkhan`** as the field's best natural experiment: same strategy, same months, mid-marked self-simulation **+431%** vs real broker fills **−3.42%/trade**. The spread flipped the sign.
- **`codewithpom`**'s stress test as the template for killing your own result: a real expanding-window walk-forward that took his headline Sharpe from 4.58 to a t ≈ 1.23 null, plus the Black-Scholes wing repricing that turned his iron condor from a capped-loss identity into Sharpe −6.71. He publishes both, and titles the README after it.
